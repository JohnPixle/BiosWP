Style guide & component specs

Source of truth for the admin design system. All tokens and component styles live in tokens.css; pages add no component CSS of their own. BEM classes, two-tier tokens (primitives → semantic; components use semantic only), dark mode via [data-theme="dark"]. See example.html for the full-page reference and shell-*.html for layout variations.

1 · Token architecture

  • Tier 1 — primitives: raw values (--gray-900, --blue-600, --space-16, --font-size-13). Never referenced by components. In a design tool: one collection, single mode.
  • Tier 2 — semantic: role aliases (--color-text-primary, --color-bg-surface, --space-md). The only tokens components may use. In a design tool: one collection with Light and Dark modes.
  • Accent knob: everything accent-colored routes through --accent / --accent-hover / --accent-soft. Resolution: explicit brand color → the user's wp-admin color scheme (WP core's --wp-admin-theme-color) → native admin blue. Static previews can force a scheme with data-admin-scheme (try the picker, top right).
  • Dark mode changes color roles only. Type, spacing, radius and size roles are mode-independent.
  • The wp-admin shell (.shell) is fixed-dark in both modes and uses primitives directly — it mimics wp-admin chrome and is not part of the plugin system.
  • Naming: --color-{category}-{role} for color; --{scale}-{step} for everything else.

1b · Customization knobs

The kit reskins through a small set of variables — the settings shared with the setup skill. Everything else derives.

  • Accent (3): --accent · --accent-hover · --accent-soft — brand color; falls back to the user's wp-admin scheme, then admin blue. Presets: data-admin-scheme.
  • Spacing engine (1): --space-unit (4px) — every spacing step is a multiple (×1 ×2 ×4 ×6 ×10). Presets: data-density="compact" (3px) / "relaxed" (5px). Type and control sizes stay fixed by design. Try the density picker, top right.
  • Roundness (two-tier): --radius (4px) — master, drives the container tier (cards, panels, notices); --radius-control (half the master = 2px) drives buttons, inputs, and other crisp parts. One dial governs both — 0 squares the UI. Per-part overrides: --radius-button · --radius-card · --radius-input. Pills (--radius-full: badges, toggle) stay round by design.
  • Vertical rhythm (4): --gap-tight · --gap-content · --gap-section · --gap-label (field label → its controls, 12) — stack gaps; also follow the spacing engine.
  • Layout widths (8): --width-content-max 1100 · --width-aside 300 · --width-onboarding 560 · --width-drawer 420 · --width-modal 440 · --width-popup 320 · --width-toast 360 · --width-filter-menu 240.
  • Breakpoints (700px setting stack, 960px columns stack) are constants — media queries cannot read custom properties.

  • Text on light surfaces: --color-text-primary / --color-text-secondary. On accent fills: --color-text-on-accent.

3 · Type, spacing, radius, size

--heading-xl · 21–26 / 400Page title (one per page, fluid)
--heading-lg · 20 / 600Guide sections, rare in-plugin
--heading-md · 16 / 600Card titles, plugin brand
--heading-sm · 15 / 600Sub-groups, modal titles, empty-state titles
--text-lg · 14Page lead paragraph, tab labels
--text-md · 13Base body, buttons, form controls, table cells
--text-sm · 12Hints, meta, badges, code chips
--text-xs · 11Table column labels
  • Spacing roles map to primitives: --space-xs 4 · --space-sm 8 · --space-md 16 · --space-lg 24 · --space-xl 40. No raw pixel spacing outside tokens.css.
  • Radius is two-tier: --radius-control 2 (buttons, inputs, chips, checkbox) · --radius-md 4 (cards, panels, notices, wells) · --radius-full (badges, toggle).
  • Size roles: --size-control 16 (checkbox/radio) · --size-step 24 · --size-icon-tile 36 · --size-icon-tile-lg 44 · --width-input-narrow 80 · --width-sidebar 160 · --width-setting-label 180.
  • Cards stack with --space-lg; content within a card steps in --space-md; label-to-control gaps are --space-xs.
  • Font is the system stack only — no webfonts in the plugin admin.
  • Line heights are tokens: headings --leading-heading (1.25), body --leading-body (1.5). Never set raw line-height values.
  • Hierarchy rule: the page title is the largest text on any screen. The plugin brand is --heading-md and must never outweigh it.
  • --heading-sm (15) is intentionally one px above --text-lg (14) so headings and large body text are never ambiguous.

4 · Icons

Icon

.icon

Tabler icons only, as inline SVG sprite symbols — clean markup, currentColor for free, zero external requests.

Usage
<svg class="icon" aria-hidden="true"><use href="#i-{name}"/></svg> — each example includes the SVG symbols it uses from icons/
Modifiers
.icon--sm 14px · default 18px · .icon--lg 22px
Rules
  • Tabler set only. Icon name in code = tabler icon name = component name in a design tool.
  • Icons inherit currentColor from context — never set icon color directly.
  • Always aria-hidden="true"; icons are decorative, the adjacent label carries meaning.

5 · Components

The component specs live on six group pages. Every UI element must be one of these components; something new goes on its group page and in tokens.css first — never as page-local CSS.

  • Navigation — tabs (+ card/boxed/vertical/segmented), subnav, views, page header, pagination, stepper. Composition patterns →
  • Forms & actions — button, field, setting row, selection controls, copy field, tag input, repeater, filter, action menu, save bar.
  • Containers & chrome — card family, stack, layout variations, plugin header, admin bar, admin menu.
  • Data — table, list table, badge, stats, checklist, disclosure.
  • Feedback — notice, empty state, modal, toast, drawer, popup, tooltip, loading states, progress.
  • Add-ons & AI — add-ons, pricing, upsell, license, link list, chat, AI suggestion.
