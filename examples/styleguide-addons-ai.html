Anatomy
.addon.addon--pro > __top (__icon [lock] + .badge--pro) + __body + __footer (upgrade .button--primary + __note)
Rules
  • Locked extensions keep full descriptions — sell the value, mute only the icon tile.

  • Only a filled badge (--pro) may overlay the thumb — it carries its own background; dot badges have none and would fail contrast over an image.
  • Grids may mix unlocked and locked add-ons; optionally end the screen with one .upsell banner.

Anatomy
.upsell > __icon + __content (__title + __description) + __actions; .badge--pro is a badge modifier (no dot, accent fill, uppercase)
Rules
  • .badge--pro marks locked controls inline; the control itself renders disabled.
  • One upsell banner per screen, maximum — never stack them.
  • Banner uses --color-action-soft, not a state color: upsell is promotion, not a warning.

Anatomy
.license > __status (badge/spinner + __meta) + [__connect (.button--primary + __or)] + __form (.field__input + .button) + [__help]
States
badge default = unlicensed · spinner = connecting · --success = active (button says Deactivate) · default "Expired" = lapsed (Renew; updates/support pause but the plugin keeps working) · --danger = invalid (meta carries the error, __help surfaces troubleshooting)
Rules
  • Key input is monospace; mask stored keys as XXXX-XXXX-XXXX-XXXX.
  • Offer __connect (account link) above the key fallback where the product supports it; Activate/Renew is --primary, Deactivate is the outline default.
  • Expired degrades updates and support first — never brick installed functionality (WordPress.org forbids trialware lockouts).
  • Attach __help under a failed or expired state; keep it to a few plain-language causes plus one guide link.
  • See shell-sidebar.html for the aside-widget placement.

.chat

AI assistant conversation panel: log of messages, typing indicator, suggested prompts, composer. Lives in a flush card or a drawer. Static markup — sending/streaming is host-page JS.

Second paragraph of the reply.

AI responses may be inaccurate. Verify before applying.

Elements
__log · __message (+ --user) · __body · __meta · __bubble · __typing (3 × __dot) · __actions / __action · __suggestions / __suggestion · __composer · __input · __footnote
Rules
  • Assistant messages align left with the sparkles avatar; user messages mirror right with the soft accent bubble. Colors are semantic — dark mode is free.
  • The log is role="log"; the typing indicator is role="status"; action buttons are icon-only and carry aria-labels.
  • Every chat ships the __footnote disclaimer. Data-flow consent belongs in a .notice on the settings screen, not in the chat.
  • Prefer .ai-suggestion for field-level AI; chat is for when conversation itself is the feature.

AI suggestion

.ai-suggestion.badge--ai

Inline AI proposal for a nearby field: generated value + Accept / Regenerate / Discard. The badge marks AI-generated or AI-powered content.

Suggestion title

AI

Generated suggestion text goes here. One or two sentences proposed by the model for the field above.

AI generated
Elements
__header (sparkles icon + __title + optional badge--ai) · __body / __text · __actions
Rules
  • Accept is the only --primary; Regenerate is outline; Discard is --link. Accepting writes the value into the field — the suggestion never replaces the field.
  • “Generate with AI” triggers are outline buttons with the sparkles icon — never --primary (generation is an offer, not the screen’s main action).
  • badge--ai is informational, never clickable; usage limits reuse .progress; consent reuses .notice.
