Navigation patterns

Depth comes from composing across screens (submenu → page tabs → drill-in), not stacking bars: each screen keeps one chrome .tabs strip, one secondary nav. Rules: docs/agent-heuristics.md §2b. Component specs: Navigation.

The depth ladder

  1. wp-admin menu item — the plugin itself.
  2. Sidebar submenu — its screens (Dashboard / Redirects / Settings).
  3. Chrome .tabs — sections of a screen (Settings → General / Advanced).
  4. Drill-in — a breadcrumb into a subpage with its own .tabs--card.

.views (list filtering) is orthogonal, not a level — coexists with any above. Push a level down when settings outgrow one tab row.

Tabs as primary

single menu-item plugin

No submenu — the topbar .tabs strip is the primary nav. For a single admin-menu item with few screens.

Titled second level under a tab

the labeled-parent rule

A level below the primary .tabs: the tab picks the section, a strip beneath picks the page. The strip needs a title directly above it (the .page-header or a card header) — the title anchors the level; two strips never stack bare. Three arrangements, same rung — pick by weight and scope.

Lightest: .page-header → .subnav--links, all on the canvas. For a few light pages.

General Advanced Permissions

Opt-in only — the direct stack, with a compound title: .subnav--tabs immediately under the primary strip, no title between. The connected blocks fuse with the strip above; the anchoring cost (one title can only name one level) is repaid below the stack — a compound .page-header title naming the full path ("Settings: General") anchors both levels at once. Agents never build this unprompted; on explicit request, give a heads-up, then build it — always with the compound title below.

Multi-level breadcrumb

≥2 ancestors on drill-ins

Real consoles go list → item → sub-item. The .page-header__breadcrumb simply carries two (or more) ancestor links; every ancestor is a link, the current level is plain text. The back button targets the nearest ancestor, not the list.

Back to list, state preserved

row-reached detail screens

Mandatory on any screen reached from a list-table row: the breadcrumb ancestor / back button returns to the originating list state — the URL keeps the list's .views filter and pagination. The user left page 3 of "Active"; back must land on page 3 of "Active", not page 1 of "All". The well shows the actual back href.

Section index

.section-index — long settings pages

For settings pages past ~2 viewport heights: an anchor-link table of contents. Static by default; --sticky (shown here, in a .columns aside rail) only with root scroll-padding-top — which the component ships — and the kit's visible keyboard focus. Not a nav level: like .views, it's orthogonal to the ladder. Pure anchors + CSS, no JS.

Views — an orthogonal axis

filtering, not a nav level

.views filters one collection into subsets — pipe-separated links with counts, above the list-table. Not a level. Distinct from .subnav's spaced, count-less links.
