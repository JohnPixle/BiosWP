Navigation

Section navigation and wayfinding: tabs and their variants, subnav, views, page headers, pagination, and wizard progress. These specs show each part in isolation — for how they compose across screens (the depth ladder and worked layouts), see navigation patterns. Elements
.tabs__tab
Modifiers
.tabs__tab--current (pair with aria-current="page") · .tabs--card (sub-navigation inside a .card--flush, below the card header; smaller type, underline hugs the label) · .tabs--boxed (same sub-navigation rung as --card, folder tabs that fuse into the panel below — stronger current-page anchor for dense screens) · .tabs--vertical (same rung, rail layout for a .columns two-column screen; current state is an accent-fill, not an underline) · .tabs--segmented (inline button-group control for a small 2-4 equally-weighted toggle, not a section list — the one variant that doesn't require a breadcrumb; square radius matches .button, not a pill shape)
Rules
  • At most one chrome .tabs strip per screen: it's the primary nav for a single menu-item plugin, or a page's section nav under the header when the sidebar submenu is primary (the WP settings-tabs pattern). Never two competing strips.
  • --card/--boxed/--vertical are page-level sub-navigation only; never use them in parallel with a chrome .tabs strip on the same screen, and never use two of them together.
  • In card placement the tab panel content goes in .card__body, directly after the tabs row.
  • --segmented is for interchangeable views of the same thing (Visual/Code, Day/Week/Month) — if the options are a section list instead, use --card/--boxed/--vertical or .subnav.
  • Composition: see the strip working as primary nav, and stacked with subnav and drill-in, in navigation patterns.

Subnav

.subnav.subnav--links.subnav--tabs

Secondary navigation strip directly under whichever primary nav is in use — chrome tabs, or directly under .page-header when the sidebar submenu is primary: pages of a section (navigation level 2). Two variants — pick one.

--links — spaced text links, the lightest way to add a level

--tabs — connected block tabs; the current page takes the body background and blends into the content below

Subnav label Subnav label Subnav label
Anatomy
nav.subnav.subnav--links|--tabs > __link — no pipes, no counts (those are the .views signature)
Modifiers
.subnav--links (spaced text links; --current is bold, text-primary) · .subnav--tabs (block tabs filling the row; --current takes the canvas/body bg and drops the bar border to blend into the content below) · .subnav__link--current (pair with aria-current="page")
Rules
  • Navigation ladder: primary = sidebar submenu OR (single menu-item) a top-level chrome .tabs strip · secondary (max one) = chrome .tabs under the header (WP settings-tabs) OR .subnav OR the .tabs--card/--boxed/--vertical drill-in patterns · .views = filtering, not a nav level.
  • Default home: directly under the titled .page-header (full-bleed, outside any card) — never directly under another nav strip. A strip needs a title above it (the labeled-parent rule, heuristics §2b).
  • --links is the quiet default under a header. --tabs exists for one composition only — the bare direct stack fused under the chrome .tabs strip, which agents build on explicit user request only (heads-up about the anchoring cost, then comply). On the canvas under a header, the stronger-anchor option is .tabs--boxed, not --tabs.
  • Composition: the "tabs + subnav" and "submenu + page tabs" layouts are worked out in navigation patterns.

Section index

.section-index

In-page table of contents for long settings pages (~2+ viewport heights): anchor links to the page's sections. Pure anchors + CSS — no JS. Not a nav level; it points inside the current page.

Anatomy
nav.section-index > __title + __list > li > __link — always an aria-labeled nav
Modifiers
.section-index__link--current (pair with aria-current="true"; dark bold — "colored = clickable, dark = you are here") · .section-index--sticky (pins inside a .columns__aside rail)
Rules
  • Optional, for pages exceeding ~2 viewport heights — shorter pages don't need one.
  • Static by default. --sticky only inside a .columns aside rail; the kit sets root scroll-padding-top so anchor jumps don't hide section titles, and links keep the visible keyboard focus.
  • Not a nav level: it coexists with any primary/secondary nav (like .views, it's orthogonal to the ladder).
  • Composition frame: navigation patterns.

Page header

Title + lead at the top of every plugin screen. Exactly one per page.

.page-header__title · .page-header__lead · drill-in: __breadcrumb (__back icon button + crumb links + __crumb-sep)
Rules

Anatomy
ul.views > __item > __view (+ __count) — pipe separators are CSS-generated between items
Modifiers
.views__view--current (bold, text-primary; pair with aria-current="true")
Rules
  • Filtering, not navigation: views switch subsets of the same collection. Different content → .tabs.
  • Place directly above the list-table, inside the .card--flush after the card header.
  • Counts are optional but recommended; they stay regular weight inside the bold current view.

Step variants
default (upcoming) · --current (pair with aria-current="step") · --complete (marker shows Tabler check)
Rules
  • Use the numbered variant for 3–5 step wizards; the bar variant when space is tight or steps are many.
  • Bar fill width is set by the host page as a custom property (style="--fill: 50%"), never a raw inline width.
  • Completed markers use the accent fill; only one --current step at a time.
