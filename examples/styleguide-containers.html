Layout variations

.columns.onboarding.plugin__body--full

Shell layout variations. Full-page references: shell-fullwidth.html, shell-sidebar.html, shell-onboarding.html.

.plugin__body--full
Removes the 1100px max-width — for list-table screens. See shell-fullwidth.html.
.columns
.columns > __main + __aside — main content + 300px aside of widget cards (license, newsletter, links, .upsell--stacked). Stacks below 960px. See shell-sidebar.html.
.onboarding
.onboarding > __panel — replaces topbar/tabs/body with one centered 560px panel (stepper + card). See shell-onboarding.html.
Rules
  • Aside widgets are plain .cards — no special widget component.
  • All shells share the same .admin-menu markup in the first grid slot.
  • Onboarding keeps the wp-admin shell; only the plugin chrome is removed.

Admin bar

.admin-bar

The wp-admin top bar as a component, for full-screen mockups and previews. Chrome like .admin-menu: fixed wp palette, real dashicons, metrics measured on WP 7.0, excluded from dist. Dropdowns open on hover/focus (CSS-only).

Elements
__item · __icon (20px dashicon, dimmed base) · __badge (updates count) · __bubble (moderation count, wp red) · __spacer · __avatar (16px square) · __menu > __submenu (+ --right) > __submenu-item · __user (64px avatar + __user-name/__user-login)
Rules
  • Hover, focus, and submenu-open share one state (bar hover blue on the darker fill) — measured wp behavior, no transitions.
  • Dropdowns are CSS-only (:hover/:focus-within), like wp's no-JS fallback; the right cluster uses __submenu--right.
  • Same chrome rules as .admin-menu: dashicons allowed here only; never render inside real wp-admin (dist drops this section); not replicated: <782px mobile mode, nested flyouts.
  • Icon-only items carry aria-labels; counts are literal placeholders.

Admin menu

.admin-menu

The wp-admin sidebar as a component, for full-screen mockups and previews. Chrome, not plugin UI: fixed wp palette in both modes, real dashicons, metrics measured on WP 7.0. Excluded from the dist build — WordPress renders the real menu.

Elements
__item (+ --current: accent fill + canvas arrow) · __icon (20px dashicon, dimmed base) · __bubble (update count) · __separator · __submenu-item (+ --current)
Rules
  • Icons are real WP dashicons (reference/icons/wp-*.svg, GPL) — the one exception to Tabler-only; never use them in kit components.
  • Fixed wp palette in both modes; the current-item fill rides --accent, so admin-scheme presets flow through.
  • In the demo shell it is the first grid child, so .shell's first column places it — no slot class needed. Never render it inside real wp-admin — core owns the menu there (dist drops this section).
  • A custom plugin item without its own icon uses wp-admin-generic — wp's default.
