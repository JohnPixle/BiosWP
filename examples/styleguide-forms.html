Selection controls

.checkbox.radio.toggle

Selection controls. Checkbox = independent options, radio = one of a set, toggle = immediate on/off state.

Anatomy (toggle)
label.toggle > input.toggle__input + span.toggle__track + span — the input is visually hidden, the track renders the switch.
Rules
  • Toggle applies immediately; checkbox waits for a save action. Don't mix the semantics.
  • All three share the same hint pattern: __hint in secondary text. Default renders inline after the label (with an em-dash); the --hint-below variant puts it on its own line.

Copy field

.copy-field

Read-only value with a copy button: API keys, shortcodes, webhook URLs. Input and button fuse into one control.

Anatomy
input.field__input.copy-field__input[readonly] + button.button.copy-field__button
Rules
  • Value renders monospace; the input is always readonly.
  • The copy action itself is host-page JS; on success show a .toast or swap the button label.
  • For license keys use .license — it owns masking and validation states.

Upload

.upload

File input. Default: native input with a styled choose button, composed with a .button for the submit action (the WP install/import row). Dropzone variant for drag-and-drop.

Anatomy (row)
.upload > input.upload__input[type=file] + .button
Anatomy (dropzone)
label.upload.upload--dropzone > hidden __input + __icon + __text + __hint
Modifiers
--dropzone · --dragover (state, host JS toggles it)
Rules
  • The native input does the work — selection display, keyboard, form posting. No JS required for either form.
  • Dropzone is a label wrapping a hidden input: click and keyboard come free; focus-within draws the ring. Drag-over = host JS toggling --dragover.
  • Row form pairs with an outline .button for the submit action; the button stays disabled until a file is chosen (host JS).
  • Reach for --dropzone only when drag-and-drop genuinely helps (bulk/media); install/import rows stay the default form.
  • Validation feedback → the .field error pattern or a .notice, never custom styling here.

Tag input

.tag-input.tag.tags

Multi-value input: type to add tags; each chip removes with its x. Outside the input, a .tags row shows the same chips statically or as links.

Tag label Tag label Tag label

.tags — static / linked chips outside the input

Tag label Tag label Tag label
Anatomy
.tag-input > .tag (label text + __remove) + __field; composes inside .field for label + hint. Display: .tags > .tag (span, or a when it navigates) — no remove button outside the input.
Rules
  • Enter commits the typed value as a chip; Backspace on empty input removes the last chip (host page behavior).
  • __remove is a real button with aria-label="Remove tag".
  • The wrapper carries the input border; the inner field is borderless. Focus ring via :focus-within.
  • Linked chips keep chip colors — hover strengthens the border, not the text; the shape is the affordance. No weighted "clouds": filtering a collection by tag with counts is .views.

Repeater

.repeater

Sortable row group (ACF-style): each row has a drag handle, a content slot of fields, and a remove button, plus an add-row footer.

Elements
__row · __handle · __content (flex slot of fields) · __remove · __footer
Rules
  • Markup-only: drag-to-reorder is host-page JS; the handle is the affordance.
  • Rows hold controls, not prose — for collapsible content rows use .panel instead.

Conditions

.conditions

Rule builder for conditional logic ("show/run when …"): subject · operator · value per row, composed from field controls. Rows AND within a group; groups OR between them.

and
or

Elements
__group (AND set, on the subtle bg) · __row ("When"/"and" __connector + subject/operator/value controls + __remove) · __or (centered label between groups) · __footer (add buttons)
Rules
  • Grammar is fixed: rows AND within a group, groups OR between them — never mixed operators inside one group.
  • Controls reuse field__select/field__input; the value control varies by subject (select, input, date) — swapping it is host-page JS, as are add/remove.
  • Row logic only — for reorderable content rows use .repeater; for filtering a list use .filter/.views.

Filter

.filter

Advanced filter dropdown. Default: single-select list. --multi: checkbox options with a search field. Advanced component — prefer plain selects for simple cases.

Anatomy
.filter > .button (trigger) + __panel > [__search] + __options > __option (+ __option-check) + [__footer]
Variants
default (single-select, check marks current) · multi-select (checkbox options + __search + __footer with Clear/Apply)
Rules

  • Show the search field only above ~7 options.
  • Options list scrolls past 240px.

Action menu

.menu

Anchored action menu (kebab, dots-vertical trigger): row and card actions that don’t fit inline. Panel shown statically here; open/close is the host page’s concern.

Elements
__panel (anchored dropdown) · __item (button or link) · __divider
Modifiers
__panel--right (right-aligns to the trigger) · __item--danger
Rules
  • Three or more actions, or any destructive one → menu; one or two safe actions stay inline as buttons/links.
  • --danger items sit last, behind a __divider, and still confirm via .modal.
  • For filtering a collection use .filter; the menu is for actions only.

Save bar

.save-bar

Full-width sticky bottom action bar for settings screens. Sticks to the viewport bottom while unsaved changes exist.

Unsaved changes message goes here.
Anatomy
.save-bar > __message + __actions
Rules
  • Place as a sibling after .plugin__body (last child of the plugin container) so it spans the full width; position: sticky; bottom: 0 keeps it visible while scrolling.
  • Show only while there are unsaved changes; saving fires a toast ("Changes saved").
  • One --primary button; secondary action is optional (e.g. "Discard").
